# VortexPlatform

System clients and system-backed views; features reach the system only through them, so tests can substitute them. The notch window and the menu bar icon are not here: they belong to Shell. Debug builds also hold QA mode in QA/ (App/docs/README.md): `QA`, the commands, state and snapshots, the window guard the shell installs first (`QA.guardWindows()`: a window on a display is a violation and is ordered out), and every client simulated in `useQAClients`; a new client gets a line there too, which a test checks.

| File | What it covers |
| --- | --- |
| Clients/HotkeyClient.swift, KeyboardLockClient.swift | global shortcuts: a module declares its own `Hotkey`, listens with `presses`, shows `HotkeyRecorder` (KeyboardShortcuts' field, as wide as its words in the app's language need, Ukrainian from App/KeyboardShortcuts), and `shortcut` gives its keys as menus show them; every key held back for cleaning, by an active event tap on the main run loop (keys, modifiers, brightness, sound and media; never the pointer), turned back on when macOS turns it off, needing Accessibility, asked for only on the user's click |
| Clients/PasteboardClient.swift | copies made in any app (checked twice a second), writing to the pasteboard, `AppInfo` |
| Clients/FileClient.swift, AppInstallClient.swift | file info (size, folder, whether this user may run it), reading, writing, copying, deleting, Show in Finder, folder picker, watching a folder; where this copy of Vortex runs from (under App Translocation, the original, from Security's SecTranslocate functions looked up at runtime), the app at a path with its version (`AppVersion`: compared as numbers, "0.1.2 (17)" with the build), and moving this copy to /Applications: the app there to the Trash whole (when it can't, nothing changes), this one renamed there (copied across volumes or from a translocated path), quarantine off, a failure undone (the old app back from the Trash); "Don't ask again" in UserDefaults, release builds only |
| Clients/AppsClient.swift, FrontWindowClient.swift, QuickLookClient.swift, ActiveAppClient.swift | running apps, `AppIcon`, opening an app or a page in it; the app in front with its window title and browser page; the Quick Look panel, which Vortex windows hand over through `QuickLook`; apps coming to the front and quitting, and an app's window frames (bounds need no permission) |
| Clients/LaunchAtLoginClient.swift, SystemClient.swift, SoundClient.swift, NotificationClient.swift, SystemSettingsNamesClient.swift | System Settings' own names for Privacy & Security, its panes and Notifications, read from its extensions' tables (loctable or lproj) in the system's language, not Vortex's, and as this macOS version has them (nil where it has none); `QuitRequest`: only a quit System Settings asks for («Quit & Reopen») reopens Vortex, by `reopenAfterQuit`, the relaunch's helper without the quit; login item, and whether an earlier release build set it up (`isSetUp`); theme, interface language, relaunch (the app opens again once this process is gone; if it is still there after about 10 s, as when the quit was cancelled, nothing opens), also from another path (`relaunchFrom`, after the move to /Applications), quit; system sounds by name; notifications with buttons, shown even while Vortex is active, each press telling which notification it was on, taken back by id prefix (needs the app bundle, so not under `swift test`) |
| Clients/ScreenCaptureClient.swift, TextRecognitionClient.swift, Views/ScreenOverlay.swift | A display as it looks (Screen Recording's status and request are in `PermissionsClient`), without Vortex's windows (`Screenshot`, `ScreenImage`: crop, PNG, HEIC, read back decoded); text on images by Apple Vision, offline; a window over a whole display, above everything, that gives way when another app comes to the front: with Vortex brought to the front (`show`) or the app in front and the keyboard left as they are (`showKeepingFront`: it never takes the keyboard, takes the keys pressed in Vortex meanwhile and keeps the shell's window open) |
| Views/DragSource.swift, DropTarget.swift, ScrollDragArea.swift, EditingShortcuts.swift, FileThumbnail.swift, ColorWell.swift, ReduceMotion.swift; OutsideActivity.swift (not in Views/) | drags out (`DragSourceArea`: hover, clicks, several items, which the other app may copy or link but never move, as Transporter takes an .ipa only from a drag that may link; a press with nothing to drag stays a click) and in (`dropTarget`); scrolls and presses on a control such as the timer's drum (`ScrollDragArea`); the standard editing shortcuts for panels without a main menu, also under Cyrillic layouts (`EditingShortcuts`); Quick Look thumbnails made in the background, `FileIcon`, `FileName` (a name as Finder shows it in the app's language, such as Downloads, its extension always kept); a color picker whose panel floats above Vortex; `reduceMotion` and `ReduceMotion.isOn`, macOS's Reduce Motion or on with `--qa-reduce-motion`, for new animations such as the onboarding's (today's views read `accessibilityReduceMotion`); whether a drag out, Quick Look, the folder picker or a picture over the whole display is in use, so the shell keeps the window open (`OutsideActivity`) |
| Clients/KeychainClient.swift, CommandClient.swift | secrets in the login keychain by service and account; a command in the user's shell with what their terminal's shell exports (asked from a login, interactive shell without a terminal, so `.zshrc` counts; again after a startup file changes, also through a link or under ZDOTDIR, after 10 minutes or after a command isn't found; the login profile only if the shell doesn't answer in 10 s), no input, none of Vortex's environment and a time limit, stopped with everything it started, also when Vortex exits |
| Permissions/PermissionsClient.swift, LivePermissions.swift, PermissionFeed.swift, PermissionRules.swift, SimulatedPermissions.swift | what macOS says about notifications, Accessibility, Screen Recording and the pasteboard, never prompting: read at once, then again on macOS's change signal, when an app becomes active, on `refresh()` and once a second during frequent checks, one read at a time, telling only changes (PermissionFeed, tested with its own read and clock); Screen Recording counts as at launch (`CGPreflightScreenCaptureAccess`), after that a grant shows by other apps' window titles and is confirmed once by ScreenCaptureKit, only after Vortex requested it: working now is `granted`, else `grantedAfterRestart`, and titles gone again mean it was turned off; the pasteboard is `notGranted` only while macOS says `.ask` or `.alwaysDeny` (macOS 26.4 says `.alwaysAllow` while it doesn't enforce the privacy: `notNeeded`, like `.default`); asking for one: macOS's prompt the first time, and the pane too if macOS shows nothing (no alert or System Settings within 1.5 s; notifications back within 1 s unanswered), the pane after that; what Vortex asked for in DataFolder/permissions.json; a simulated macOS for tests and QA mode, debug builds only |
